# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

Интерактивный веб-справочник по спецификации ARINC 424-15 (формат навигационных баз данных авиации), публикуемый через GitHub Pages (Jekyll, тема из `_config.yml`). Три независимых направления работы:

1. **Веб-страница-парсер** — `index.html` + `Scripts/string_to_table.js`: пользователь вставляет строку записи ARINC 424 (132 символа фиксированной ширины), JS разбирает её по позициям и выводит таблицу полей со ссылками на определения из спецификации. Ниже на странице — дерево всех типов записей (section/subsection codes) на `<details>/<summary>`.
2. **Конвейер извлечения PDF** — подготовка текста `Arinc424-15.pdf` для подачи в LLM.
3. **`wiki_arinc_structure.md`** — структурированный справочник по спецификации для вики (~6200 строк): дерево всех типов записей в `<details>`, таблицы полей всех записей главы 4 (4.1.2-4.1.30 и Heliport 4.2: HA, HC, HD/HE/HF, HS, HV), со ссылками 5.N, внизу — раздел «5.0 FIELD DEFINITIONS» с дословными определениями полей (5.2-5.225; поля дополнений 5.226-5.253 пока не внесены). Глава 4 закрыта полностью, «заглушек» не осталось.

Сборки, линтера и тестов нет. Проверка — открыть `index.html` в браузере (например, `python3 -m http.server` из корня) и вставить тестовую строку записи.

## Команды

```bash
python3 extract_arinc.py   # PDF → текст страниц (pdfplumber) и таблицы (camelot) в arinc_extracted/
python3 chunk_text.py      # arinc_extracted/page_*.md → чанки по 600 слов, перекрытие 80, в arinc_chunks/
```

- В `extract_arinc.py` захардкожен абсолютный путь к PDF — править при переносе.
- `arinc_extracted/` (579 страниц) и `arinc_chunks/` (481 чанк) генерируются этими скриптами, находятся в `.gitignore` и в git не хранятся; сам PDF (21 МБ) — в репозитории.

### Карта страниц PDF и особенности извлечённого текста

- Печатная страница N ↔ `arinc_extracted/page_(N+13)_text.md` (смещение +13; печатная 72 → `page_085`).
- Главы (печатные стр.): 1.0 Introduction 1-3; 2.0 Glossary 4-6; 3.0 Navigation Data 7-12; 4.0 Record Layout 13-52 (4.1 Master Airline User File, 4.2 Master Helicopter User File); 5.0 Field Definitions, поля 5.1-5.225, 53-119; 6.0 Encoding Standards 120-123; 7.0 Naming Conventions 124-135; Attachments 1-5 136-237; Appendixes 238+; в хвосте PDF — Supplements 11-15 с собственной нумерацией.
- Поля дополнений 5.226-5.253 — на печатных стр. 115-118 (`page_128`-`page_131`).
- В главе 4 извлечённый текст интерливит строки левой и правой колонок оригинальной вёрстки; артефакты вида «c-N» — маркеры вёрстки, при цитировании игнорировать. Таблицы макетов восстанавливать через `pdfplumber.open('Arinc424-15.pdf').pages[N].extract_tables()` по конкретной странице.
- Таблицы из camelot (`arinc_extracted/table_*.md`) — мусор (распознаны повёрнутые тексты), не использовать.

## Архитектура

### Парсер записи (`Scripts/string_to_table.js`, 586 строк)

Один большой набор вложенных `switch`: 1-й символ (record type) → 5-й (section code) → 6-й или 13-й (subsection code) → поля записи. Для каждого поля выводится сообщение вида `значение: Имя [позиции]` со ссылкой на картинку из `References/`.

Ключевая деталь: подписи позиций в выводе — **1-базовые по спецификации** (`[14-16]`), а `input.substring(...)` в JS — 0-базовый. Код выдерживает сдвиг: `substring(13,16)` подписан как `[14-16]`. При добавлении полей следить за этим соответствием.

### Картинки-определения

- `References/5_NNN_Field_Name.png` — снимки определений полей из секции 5 спецификации (нумерация 5.NNN совпадает с параграфами спецификации).
- `Tables/XX_Record_Name.png` — макеты записей по типам, например `ER_Enroute_Airways.png`; для SID/STAR/Approach одно изображение на три кода (`PD_PE_PF_Airport_SSAs.png`).

### Дерево типов записей — в двух местах, поддерживать синхронно

`index.html` (секция «Спецификация ARINC 424-15») и `wiki_arinc_structure.md` описывают одно и то же дерево section/subsection кодов, но для разных сред: HTML-версия ссылается на локальные `References/` и `Tables/`, markdown-версия — на `uploads/` вики (содержит и сгенерированные картинки record layout). При добавлении нового типа записи обновлять оба файла.

`wiki_arinc_structure.md` — основная база данных проекта по содержимому спецификации. Согласованный с пользователем формат: в дереве — только таблицы полей (колонки | поле (длина) | ссылка 5.N), без аннотаций; расхождения и опечатки источника помечать сносками `[^...]` внизу таблицы; дословные определения полей — внизу файла в разделе «5.0 FIELD DEFINITIONS», в порядке возрастания номеров.

## Типичный сценарий: добавить поддержку нового типа записи в парсер

1. Найти макет записи и определения полей в PDF (карта страниц выше; `extract_arinc.py` при необходимости перегенерировать).
2. Добавить ветку в соответствующий вложенный `switch` в `string_to_table.js`, следуя существующему стилю (проверка `input.length >= N` перед каждым срезом, `default: "... ???"` для неизвестных кодов).
3. При необходимости добавить картинки в `References/` и `Tables/`.
4. Обновить дерево в `index.html` и `wiki_arinc_structure.md`.

## Типичный сценарий: расширить `wiki_arinc_structure.md` (например, внести поля дополнений 5.226-5.253)

1. Найти текст поля в `arinc_extracted/page_*.md` по карте страниц выше.
2. Вставить блок `<details>` в раздел «5.0 FIELD DEFINITIONS» в порядке возрастания номеров — между уже вставленными номерами не должно быть пропущенных (проверить grep'ом по `<summary>5\.`).
3. В дерево — только таблицы полей; расхождения с источником — сносками `[^...]`.
